# 원문과 반대 근거를 검토하는 방법

## 주장–근거 대조

관련 원문을 실제로 다시 열고 다음을 확인한다.

1. **신원과 현재성:** 저자/기관, 제목/DOI, 버전/commit, 발표일, 적용 시점이 맞는가? 과거 사실을 현재 지원 상태로 바꾸지 않았는가?
2. **문맥:** 앞뒤 문장, 표 제목/각주, 부정·예외·확률 표현을 읽었는가? 원문이 부분 발췌라면 그 한계를 남겼는가?
3. **수치:** 단위·모집단·표본·분모·기간·비교 기준이 같은가? 계산을 직접 재현했는가? 18/20은 90%이고, 작은 저자 시험이 전체 제품 정확도는 아니다.
4. **의미:** 원문은 주장 전체를 지지하는가, 일부만 지지하는가, 반박하는가? 단어가 겹쳐도 다른 대상을 말할 수 있다. “아니다” 한 단어로 결론이 뒤집힌다.
5. **인식 수준:** 원저자의 주장, 정적 코드 관찰, 직접 실행, 독립 재현, 현실 적용 중 어디까지 확인했는가? LLM 심사나 자동 PASS는 독립 실험이 아니다.

인용문의 원문 존재와 의미 지지를 별도로 기록한다. 하나의 근거로 문장의 일부만 확인되면 문장을 좁히거나 나눈다. 근거가 없으면 `unresolved`로 남긴다. DOI 존재·유명 기관·최근 발행·출처 수에 점수를 주어 확률처럼 제시하지 않는다.

## 반대 근거 확인

핵심 결론마다 어떤 증거가 나오면 결론을 바꿀지 먼저 적고 검색한다.

| 주장 유형 | 유용한 반증 경로 |
| --- | --- |
| 정확도·성능 우위 | 원시 결과, 분모, 독립 평가, 실패 사례, 비교 조건, 데이터 누출/중복 |
| 현재 지원·설치 가능 | 릴리스/폐기 공지, 현재 설정·의존성, 플랫폼 이슈, 실제 실행 기록 |
| 논문 결론 | 정정·철회·후속 연구·재현 실패·반대 결과, 동일 연구의 다른 출판물 |
| 시각 품질·초안 유사도 | 동일 입력·카메라·조명·해상도·자세, 가려진 면과 작은 화면, 실패 부위 |
| 로컬·독립·무료 | 기본 네트워크 의존성, 공급자/API 요구, 상류 데이터/발표, 사용 조건 |

실제로 실행한 반증 질의와 결과만 기록한다. 계획한 질의를 검색 완료로 쓰지 않는다. 접근 실패는 별도 상태다. 없다는 결론은 어떤 검색 범위에서 못 찾았는지로 좁힌다.

충돌이 있으면 두 원문을 나란히 보존하고 버전·대상·방법·시점을 대조한다. 새 문서가 무조건 과거 실험을 반박하는 것도 아니고, 권위 높은 출처가 자동 승리하는 것도 아니다. 결론을 기각/축소/조건부로 바꾼 이유 또는 미해결을 기록한다. 뚜렷한 반대 근거가 남으면 다수결로 없애지 않는다.

## 분야별 적용

**학술 조사:** 질문·포함/제외 기준을 먼저 정하고 분야에 맞는 데이터베이스를 선택한다. 검색식·날짜·필터·결과 수·중복 처리·전문 미확보·제외 이유를 남긴다. 검색 기록(record), 출판물(report), 연구(study)를 구분한다. 초록 몇 편의 개관을 정식 systematic review라고 부르지 않는다. 연구 설계에 맞는 편향 평가가 필요할 때 별도 방법을 선택한다. PRISMA는 보고 지침이며 정확성 인증이 아니다.

**기술/오픈소스:** README뿐 아니라 핵심 설정·실행 경로·버전·이슈를 질문에 필요한 만큼 읽는다. 라이선스 파일, 패키지 표기, 모델 카드의 대상 차이를 보존한다. 설치/호환/비용이 의사결정을 좌우하면 허용된 작은 실행으로 확인하거나 미검증으로 둔다. 논문·코드·벤치마크의 모델과 예산이 다르면 수치를 한 순위표에 섞지 않는다.

**이미지/3D/영상:** 그림·표·실제 렌더가 주장 근거면 직접 시각 검토한다. 캡션, 파일 존재, JSON 검사만으로 외형을 판단하지 않는다. 입력 해시·모델 버전·카메라·조명·해상도·시각 위치·측정 정의를 남긴다. 형식 성공, 정지 렌더, 동작, 게임 런타임은 별도 상태다. 현 작업 공간의 원본 자산·REA·실행 제한을 따른다.

## 최종 결과와 종료

결론 스트레스 테스트는 [records.md](records.md)의 시나리오/검토 계약을 따른다. 같은 원천의 지지 근거 전체를 제외한 뒤 남는 근거를 읽는다. 지지 근거가 사라진 것은 주장이 거짓이라는 증명이 아니다. 여러 원천이 남아도 공유 데이터, 측정법, 이해관계가 독립성을 제한할 수 있다. 자동 시나리오와 실제 검토한 시나리오, 미검토 시나리오를 구분한다.

결론에는 중요한 사실/추론/제안, 바로 옆 출처, 실제 반대 근거, 해결되지 않은 공백, 다음 결정을 바꿀 실험을 담는다. 핵심 원문이 불충분하면 이를 명시한 부분 결과도 정상 완료다. 기다린 시간이나 원장 검사 통과로 불확실성을 없애지 않는다.

측정치는 분모와 함께 보고한다: 후보 수, 관련 원문 확인 수, 초록만 읽은 수, 주요 주장 수, 의미 대조한 쌍 수, 지지/부분/반박/미확인 수, 독립 원천 계열 수, 실제 실행 범위. 부분 지지와 미검토를 지지 성공에 넣지 않는다. 중복 출처·같은 모델의 여러 답변을 독립 증거로 세지 않는다.
